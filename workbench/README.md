GPT 默认复用当前 codex login 的 ChatGPT 登录，经本机 Codex 执行；使用 read-only 沙箱，工作台保留自己的会话和 thread。已通过真实两轮上下文测试。它不是 ChatGPT 网页聊天的直接控制或同步。也可展开可选设置，改为 OpenAI API（需要单独密钥）。Muse 默认使用已登录的 muse.ai 个人智能体，通过社区 muse-cli 读取原目录、导入并继续原聊天。GPT 网页历史仍需另行导入副本。

## 启动

双击 `start.cmd`，或者在此目录执行 `npm start`。打开 http://127.0.0.1:8790 。首次安装执行 `npm install`。要求 Node.js 22+、已安装 Codex CLI。

1. 在终端运行 `codex login`，完成登录后在工作台点击“刷新”。
2. 点击“连接 Chrome 登录”，按本机窗口说明进行一次性会话授权；步骤见 PERSONAL_MUSE.md。登录保存在本机，完成后检查连接并刷新 Muse 目录。可选 Meta 模型 API 是另一个产品，不会接管 muse.ai 原任务。
3. 优先使用上方“贾维斯”助手号入口。其他入口中的 iLink Bot 与 WhatsApp 独立配置，均需扫码确认；iLink Bot 不等同于个人助手小号。
4. 贾维斯入口自动接收好友指令，联系人列表可暂停接收。iLink Bot / WhatsApp 入口仍需在本机授权对应联系人。

WhatsApp 使用手机的“已关联设备”扫码；此版只接收其他账号的私聊，排除群聊和自己发送的消息。微信采用 iLink Bot QR 协议，入口是否可用取决于账号及平台服务。支持文字指令，暂无附件下载、文件回传或远程审批功能。

## 实际能力与限制

- Codex 使用本机 `codex exec` 和 `exec resume`，工作目录为所选项目的专用目录，默认 `projects/default`。不接管桌面应用已有聊天；可通过 CLI 恢复工作台创建的 thread。
- Codex 使用 workspace-write 沙箱，approval_policy=never；需要超出沙箱权限的操作会失败。未关闭沙箱，不提供手机提权审批。
- Muse 个人智能体使用社区 muse-cli 0.3.2，网页协议可能变化；只读列出原目录、导入原聊天、创建独立聊天、发送指令并接收回复。不通过本地 shell 执行 Muse 返回的内容。收到第一条回复不等于云端后台目标全部完成。
- 每个联系人 / 网页会话独立，同一个会话一次执行一项任务。任务结果在完成后发回原私聊。任务失败和回传失败分别显示。
- 凭据、任务和授权在本机 `data/` 保存，扫码凭据为明文，本目录不能提交到 GitHub 或分享。Meta 密钥不写入文件。管理页只监听本机回环地址。
- 需要电脑保持运行、网络能连接模型和消息服务。暂无开机自启。服务重启会将未完成任务标为中断。
